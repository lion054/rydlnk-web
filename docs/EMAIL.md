# Transactional email

Rydlnk renders transactional mail from one source:
`supabase/functions/_shared/messages.ts`. The renderer produces responsive,
Outlook-safe HTML and a plain-text alternative.

## Preview

```bash
npm run email:preview
```

Open `.email-preview/index.html`. The preview set includes company invitations,
top-up receipts, statement notices, low-balance variants, and all four auth
messages.

After changing a message or the shared renderer, regenerate the hosted-auth
templates:

```bash
npm run email:templates
```

Commit the resulting files under `supabase/templates/`.

## Hosted Supabase auth

`supabase/config.toml` applies the templates to a local Supabase stack. Hosted
Supabase projects keep their own template copy: open Authentication → Email
Templates and paste the matching committed HTML and subject for Magic Link,
Confirm signup, Reset password, and Change email.

Keep `{{ .ConfirmationURL }}` unchanged. It is the single-use link generated by
Supabase.

## Delivery

Edge Functions send through Resend and require:

- `RESEND_API_KEY`
- `INVITE_FROM_EMAIL`
- `SITE_ORIGIN`

Top-up receipts, statement notices, and low-balance warnings claim a row in
`notification_log` before delivery. The unique `(company_id, kind, ref)` index
prevents duplicate lifecycle messages.

`billing-notify` is a private scheduled endpoint. Call it with
`x-billing-secret: $BILLING_NOTIFY_SECRET`. Add `?dry=1` to inspect candidate
counts without claiming or sending messages.

## Production checks

- Verify the Resend sending domain and DKIM/SPF records.
- Send test messages to Gmail and Outlook desktop/mobile.
- Verify buttons and plain-text fallback links.
- Confirm replies go to the intended monitored mailbox.
- Never place Resend or notification secrets in `NEXT_PUBLIC_*` variables.
